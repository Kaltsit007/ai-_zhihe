## 委托

| 状态 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| ✅ | GET | /api/tasks | 列表，支持 category、status、q |
| ✅ | POST | /api/tasks | 发布委托 |
| ✅ | GET | /api/tasks/:id | 详情 |
| ✅ | PATCH | /api/tasks/:id/status | 接单、完成、取消、归档 |

字段：

- category：team、carpool、moving、volunteer、club、other
- status：pending、in_progress、completed、cancelled、archived
- location、deadline、contact、tags、urgent、pin

## 预留接口：请求 / 响应示例

预留接口现在返回：

~~~json
HTTP/1.1 501 Not Implemented
{
  "data": null,
  "error": {
    "code": "NOT_IMPLEMENTED",
    "message": "答疑详情 接口已预留，由 C 在 D2 实现"
  }
}
~~~

**这是故意留的 501**，不是故障。前端按 `error.code === "NOT_IMPLEMENTED"` 显示“功能开发中”即可。

### POST /api/questions/:id/answers

请求：

~~~json
{ "content": "带身份证到行政楼 201，周三下午人少。", "author": "匿名同学" }
~~~

成功返回 201：

~~~json
{
  "data": {
    "id": "a_xxx",
    "questionId": "q_xxx",
    "content": "带身份证到行政楼 201，周三下午人少。",
    "author": "匿名同学",
    "createdAt": "2026-11-25T10:00:00.000Z"
  },
  "error": null
}
~~~

### PATCH /api/lost-found/:id

请求：

~~~json
{ "status": "claimed" }
~~~

成功返回 200，data 为更新后的 LostFound 对象（status 变为 claimed）。

## 约定

- 登录接口用 Supabase JWT，由 A 在 D2 接入。
- 内部接口用 CRON_SECRET，不暴露给前端。
- 字段一旦确定，D1 后不随意改名；要改先改本文档并通知全员。
- 新增接口的顺序：先改本文档 → 再建 501 占位路由 → 最后填实现。
