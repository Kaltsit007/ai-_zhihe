| --- | --- | --- | --- |

字段：

- category：team、carpool、moving、volunteer、club、other
- status：pending、in_progress、completed、cancelled、archived

### PATCH /api/questions/:id

请求（标为已解决或重新打开）：

~~~json
{ "status": "solved" }
~~~

支持状态值：`"open"`、`"solved"`。成功返回 200，data 为更新后的 Question 对象；问题不存在返回 404 `QUESTION_NOT_FOUND`；状态不合法返回 400 `BAD_STATUS`。

### GET /api/questions/:id/answers

成功返回 200，data 为对应问题的 `Answer[]` 列表；问题不存在返回 404 `QUESTION_NOT_FOUND`。

### POST /api/questions/:id/answers

### GET /api/lost-found/:id

成功返回 200，data 为对应的 `LostFound` 对象；不存在返回 404 `LOST_FOUND_NOT_FOUND`。

### PATCH /api/lost-found/:id

请求（支持 `"open"` | `"claimed"` | `"closed"`）：

~~~json
{ "status": "claimed" }
~~~

成功返回 200，data 为更新后的 LostFound 对象（status 变为目标状态）；状态非法返回 400 `BAD_STATUS`，条目不存在返回 404 `LOST_FOUND_NOT_FOUND`。普通登录用户即可点击认领，接 Supabase 真库时服务端验登录后使用 `service_role` 仅放行 `status` 字段更新。

### POST /api/uploads/lost-found

- Content-Type：`multipart/form-data`，字段名 `files`（可重复多次，最多 3 张）。
- 校验规则：仅允许 `image/jpeg`、`image/png`、`image/webp`（校验 MIME + 文件头魔数），单张 ≤ 1MB，超出数量返回 400 `TOO_MANY_FILES`，格式不合法返回 400 `INVALID_FILE_TYPE`，超体积返回 400 `FILE_TOO_LARGE`。
- 双模式存储：配置 `NEXT_PUBLIC_SUPABASE_URL` 与 `SUPABASE_SERVICE_ROLE_KEY` 时自动上传至 Supabase Storage 公开桶（默认 `lost-found`）并返回公开 URL；未配置时自动降级为演示可用编码 URL（兼容只读文件系统）。
- `LostFound` 对应可选字段：`images?: string[]`（与 `0001_init.sql` 中 `lost_found.images text[]` 对齐）。

成功返回 201：

~~~json
{
  "data": {
    "urls": ["https://.../storage/v1/object/public/lost-found/2026-11/uuid.jpg"],
    "storage": "supabase"
  },
  "error": null
}
~~~

## 约定

- 登录接口用 Supabase JWT，由 A 在 D2 接入。
- 内部接口用 CRON_SECRET，不暴露给前端。
- 字段一旦确定，D1 后不随意改名；要改先改本文档并通知全员。
- 新增接口的顺序：先改本文档 → 再建 501 占位路由 → 最后填实现。
