# 06 · 部署与上线

> 目标：拿到一个评委能直接打开的公网地址。
> 前置：没有账号也能做——Vercel 和 Supabase 都能用 GitHub 登录，免费版不需要信用卡。

## 一、先想清楚：不接数据库不能上线

现在站点默认跑在内存里。本地演示没问题，但部署到 Vercel 后：

- 每次冷启动都会回到 seed，用户刚发的委托会消失
- 多个实例之间内存不共享，刷新可能看到不同数据

所以顺序是：**先建 Supabase → 再部署 Vercel**。

## 二、Supabase（约 15 分钟，免费）

1. 打开 https://supabase.com ，点 Start your project，用 GitHub 登录。
2. New project：名字随意（如 ai-zhihe），Region 选 Singapore 或 Tokyo，设数据库密码并记下来。
3. 进 SQL Editor，依次粘贴执行：
   - supabase/migrations/0001_init.sql
   - supabase/migrations/0002_tasks_schedule.sql
   两条都返回 Success 即可（0001 可重复执行，不会重复建表）。
4. 去 Project Settings → API，复制三个值：
   - Project URL → NEXT_PUBLIC_SUPABASE_URL
   - anon public → NEXT_PUBLIC_SUPABASE_ANON_KEY
   - service_role → SUPABASE_SERVICE_ROLE_KEY（只放服务端，别进前端）
5. 可选：Authentication → Providers → Email，把 Confirm email 关掉，演示时注册即可登录。
6. 可选：Storage → New bucket，名字 lost-found，勾选 Public（用于失物图片）。

## 三、Vercel（约 10 分钟，免费）

1. 打开 https://vercel.com ，点 Continue with GitHub 登录。
2. Add New… → Project → 找到 ai-_zhihe 仓库 → Import。
3. **关键一步**：Root Directory 选 apps/web（仓库根目录没有 package.json，不改这里必然构建失败）。
4. Framework Preset 会自动识别成 Next.js，Build Command 保持默认。
5. Environment Variables 填四项：

| Key | 值 |
| --- | --- |
| NEXT_PUBLIC_SUPABASE_URL | Supabase 的 Project URL |
| NEXT_PUBLIC_SUPABASE_ANON_KEY | anon public key |
| SUPABASE_SERVICE_ROLE_KEY | service_role key |
| CRON_SECRET | 自己编一个随机字符串 |

6. 点 Deploy，等 2 分钟左右，拿到 https://xxx.vercel.app 。
7. 打开地址自测下面清单。

> 定时任务：仓库里的 .github/workflows/cron-tasks.yml 需要仓库 Secrets 里配
> APP_BASE_URL（你的 vercel 地址）和 CRON_SECRET，才会每 30 分钟触发归档。

## 四、部署后自测清单

- [ ] 首页能打开，不是白屏
- [ ] /login 能注册、能登录，侧栏显示邮箱
- [ ] 未登录点“管理”会跳到 /login
- [ ] 发布一条委托 → 列表出现 → 刷新后还在（说明写进了数据库）
- [ ] 用第二个账号接单，状态变成“进行中”
- [ ] /map 瓦片能加载（国内网络下高德瓦片通常没问题）
- [ ] /info 搜“挑战杯”有结果
- [ ] 手机 4G 打开，页面没有横向滚动

## 五、如果没有 Vercel 账号 / 注册不了

| 方案 | 成本 | 适合 |
| --- | --- | --- |
| Netlify（netlify.com） | 免费，GitHub 登录 | 同样支持 Next.js，导入时 Base directory 填 apps/web |
| Cloudflare Pages | 免费 | 需要 next-on-pages 适配，Next 16 兼容性要试，不推荐赶时间用 |
| Cloudflare Tunnel | 免费，5 分钟 | 临时演示：本机跑 npm run dev，执行 cloudflared tunnel --url http://localhost:3000，得到一个临时公网地址。缺点：电脑必须开着、地址每次变 |
| 国内云服务器 | 学生机约 10 元/月 | 需要域名和备案，最麻烦，仅在学校有现成服务器时考虑 |

如果只是评委点开看一眼，Cloudflare Tunnel 是最快的兜底；但正式提交建议还是 Vercel，因为地址稳定。

## 六、常见报错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Build 报 No package.json | Root Directory 没设成 apps/web | 项目 Settings → General → Root Directory 改掉后重新部署 |
| 部署成功但登录报错 | 环境变量没填或填错 | Settings → Environment Variables 检查，改完 Redeploy |
| 数据刷新就丢 | 没接 Supabase，仍在内存模式 | 按第二节配好环境变量 |
| /admin 打不开或一直跳登录 | 没登录，或 cookie 域不对 | 先登录；自定义域名时确认没有多级子域 |
| 定时任务不跑 | 仓库 Secrets 没配 | Settings → Secrets → Actions 加 APP_BASE_URL 和 CRON_SECRET |
