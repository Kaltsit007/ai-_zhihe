## 一、项目定位

**一句话：把散落在群聊里的求助、组队、拼车、失物和校园信息，变成一张可检索、可接单、可追踪、可归档的互助地图。**

校园里的真实痛点不是“没有平台”，而是信息散在几十个群里、发完就沉、没人负责。我们要做的是把这件事结构化：

| 模块 | 解决什么 | 关键能力 |
| --- | --- | --- |
| 委托帮助 | 组队、拼车、搬行李、志愿招募、社团招新 | 分类发布、地图点位、接单、完成、自动归档 |
| 答疑与信息 | 办事流程、校园信息找不到、问了没人答 | 提问回答、学校信息库、关键词搜索 |
| 失物招领 | 丢东西只能刷群，捡到没人认领 | 丢/捡双类型、状态流转、每日机器人汇总 |

**差异点（评委能感知的）：**

1. 不是又一个论坛，而是带状态机的“任务流”：待接单 → 进行中 → 已完成 → 已归档。
2. 地图不是装饰，点位直接对应可接的委托。
3. 数据有出处：学校信息来自公开源抓取，保留来源链接。
4. 机器人把线上信息推回群里，形成闭环。

## 四、核心流程

### 4.1 委托闭环

~~~text
发布（待接单） → 接单（进行中） → 完成（已完成） → 归档（已归档）
                      └──────────────→ 取消（已取消）
过期未完成 ─────────────────────────→ 已归档
~~~

规则：归档只改状态不删数据；已完成或过期超过 7 天自动归档；演示环境用管理页手动触发。

### 4.2 答疑与信息库

提问 → 回答 → 标已解决；信息库独立搜索，展示标题、摘要、分类、来源链接；爬虫只抓公开页面，按来源去重。

### 4.3 失物招领与机器人

丢/捡提交 → 列表筛选 → 认领；每天 20:00 机器人汇总当天新增与未解决条目发群；失败写记录，管理页可重发。

**协作约束：**

1. 只改自己领地的文件，跨领地先在群里说。
2. 每天至少 1 个 PR，Draft 也可以。
3. 卡住 30 分钟就在群里问，不要自己硬试。
4. 接口改动先改契约文档，再改代码。

## 八、接口与协作约定

### 8.1 三层接口（改数据源只动中间层）

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 类型 | src/lib/types.ts | Task / Question / SchoolInfo / LostFound / Answer |
| 数据层 | src/lib/data/*.ts | 页面取数唯一入口 |
| HTTP | src/app/api/** | 与接口契约一一对应 |

### 8.2 已实现接口

/api/tasks（GET/POST）、/api/tasks/:id、/api/tasks/:id/status、/api/questions（GET/POST）、/api/school-info、/api/lost-found（GET/POST）、/api/internal/archive|crawl|digest。

### 8.3 预留接口（路径已建，返回 501，负责人填实现）

| 方法 | 路径 | 用途 | 负责人 / 启用 |
| --- | --- | --- | --- |
| GET | /api/questions/:id | 答疑详情 | C / D2 |
| GET | /api/questions/:id/answers | 回答列表 | C / D2 |
| POST | /api/questions/:id/answers | 提交回答 | C / D2 |
| GET | /api/lost-found/:id | 失物详情 | C / D3 |
| PATCH | /api/lost-found/:id | 认领 / 关闭 | C / D3 |

返回 501 是故意的，前端按 error.code 显示“功能开发中”。

### 8.4 分支与合并

| 分支 | 用途 | 合并方向 |
| --- | --- | --- |
| main | 成品，只读 | 只接收 develop 的发布 PR（D3/D5/D6） |
| develop | 集成 | 所有 feature PR 合到这里 |
| feat/fix/data/docs | 个人任务 | 从 develop 开，合回 develop |

- 每人从 develop 开分支，名字带后缀（如 feat/task-form-D）。
- PR base 选 develop；1 人 approve；CI build 绿；Squash merge。
- 详细命令见 docs/05-分支流程-develop.md。

### 8.5 每日节奏

12:30 合并窗口 → 21:00 合并窗口 → 21:30 开发日志 → 睡前 push。
