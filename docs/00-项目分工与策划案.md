# 校园综合互助平台「互助地图」分工与策划案

> 版本：v1.0（开工版）  
> 日期：2026-11-24  
> 团队：5 人  
> 当前阶段：D0，仓库和前端骨架已搭好，下一步接 P0 业务。

## 1. 项目定位

**一句话：** 把散落在群聊里的求助、组队、拼车、失物和校园信息，变成一张可检索、可接单、可追踪、可归档的互助地图。

**两个核心模块：**

1. **委托帮助**：竞赛组队、拼车、搬运行李、志愿招募、社团招新、其他。支持分类、地图点位、接单、完成、自动归档。
2. **答疑与信息**：提问、回答、搜索；内置学校信息库；失物招领提交、图片、定时群机器人汇总。

**比赛交付：** 可访问网站 + 源码仓库 + 开发日志，提交到邮箱，无答辩。因此 README、演示路径和开发日志必须能独立说明问题。

协作约束：

- E 的内容优先放共享文档/表格，由 A 或 D 导入 docs/content 和 data/seed；E 不直接改前端代码。

- 共用组件由 D 改；数据库 schema 由 C 改；接口由 A 定。

**为什么 A 要接委托后端：** D 是委托/可视化唯一写代码的人，如果后端也压给 D，D 一定堵。A 负责后端骨架、状态机和归档，D 专注前端和地图，E 负责内容和验收。

## 4. 核心流程

### 4.1 委托闭环

1. 发布者选分类，填标题、描述、地点、时间、联系方式、图片。
2. 状态为“待接单”，地图出现点位。
3. 帮助者筛选、看详情、接单。
4. 状态变为“进行中”，双方看到联系方式。
5. 完成后状态变为“已完成”。
6. 定时任务或管理页手动触发归档，状态变为“已归档”，默认隐藏。

状态机：

~~~text
待接单 → 进行中 → 已完成 → 已归档
   └──────────────→ 已取消
过期未完成 ─────────→ 已归档（定时或手动）
~~~

归档规则：

- 已完成超过 7 天，自动归档。
- 已过期超过 7 天且未完成，自动归档。
- 演示环境阈值可调成 1 天，或用管理页手动触发。
- 归档不删除数据，只设置 archived_at。

### 4.2 答疑与学校信息

1. 用户提问，填标题、正文、标签。
2. 其他用户回答。
3. 列表支持关键词和标签筛选。
4. 学校信息库独立搜索，结果展示标题、摘要、分类、来源链接。
5. 爬虫只抓公开页面，写入 school_info，按 source_url 去重。

### 4.3 失物招领与机器人

1. 失主选“我丢了”，拾取者选“我捡到”。
2. 填物品描述、地点、时间、照片、联系方式。
3. 列表按类型和状态筛选。
4. 每天 20:00，机器人把当天新增和未解决条目汇总发到测试群。
5. 发送失败时，汇总写入 bot_digests，管理页可复制重发。

## 5. 技术架构

- 前端和 API：Next.js 16（React）+ TypeScript + Tailwind CSS 4。
- 数据库、登录、图片：Supabase（Postgres + Auth + Storage）。
- 部署：Vercel，main 自动 production，PR 自动 preview。
- 地图：Leaflet，优先高德瓦片；没有 Key 就用 OpenStreetMap 兜底。
- 爬虫：Python，独立目录，输出固定 JSON 后写库。
- 群机器人：按队伍成熟方案接 webhook，定时任务调用。
- 定时任务：Vercel Cron 或 GitHub Actions，二者选一。

环境变量：

- NEXT_PUBLIC_SUPABASE_URL
- NEXT_PUBLIC_SUPABASE_ANON_KEY
- SUPABASE_SERVICE_ROLE_KEY
- NEXT_PUBLIC_MAP_KEY
- BOT_WEBHOOK_URL
- CRON_SECRET

## 7. Git 协作

- 轻量主干开发，不用 Git Flow。
- main 受保护，始终可部署；功能分支不超过 24 小时。
- 每个 PR 至少 1 人 review，A 最终合并。
- 统一 Squash and merge，合并后删分支。
- D5 之后只修 P0 阻塞 bug，不加功能。
- 详细规则见 docs/01-Git协作流程.md，新手看 docs/02-Git新人指南.md。
