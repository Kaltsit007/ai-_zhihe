# D1 走查清单（2026-11-25）

- 范围：11 个页面 + 404，本地 dev，内存演示数据
- 方法：每页按"数据 / 交互 / 边界 / 文案"四类看一遍；接口返回用后台请求核对；移动端用 375×900 实际渲染核过（页面本身没有横向溢出，只有顶部导航条按设计横向滚动）

## 1. 地图点数与文案对不上

**现象**：`/map` 顶部写"11 个活跃点"，但图上只有 8 个点，第 9 条之后的委托在地图上直接消失。

**复现**：先让委托总数超过 8 条（seed 8 条 + 新发 3 条），打开 `/map`，数图标。

**期望**：点位数和文案一致；点太多时至少说明"仅显示前 8 个"。

**实际**：标签用 `active.length` 全量计算，地图组件 `limit` 默认 8，`slice(0, 8)` 掉的不提示。

**位置**：`apps/web/src/app/map/page.tsx`、`apps/web/src/components/campus-map.tsx`

**建议**：把 limit 提到能覆盖演示量（如 30），或标签改成"已显示 8 / 共 11"。

## 2. 已取消的委托还能看见，却筛不出来

**现象**：把 t2 取消后，`/tasks` 的"全部状态"里仍有这条，带"已取消"徽标；但状态筛选只有全部 / 待接单 / 进行中 / 已完成 / 已归档，没有"已取消"。

**复现**：`PATCH /api/tasks/t2/status`，body `{"status":"cancelled"}`，再刷新 `/tasks`。

**期望**：已取消要么像归档一样默认隐藏，要么筛选里能选。

**实际**：默认显示，且无法按状态筛，用户只能靠肉眼翻。

**位置**：`apps/web/src/components/task-explorer.tsx`（`statusOrder` 少一项；`status === "all"` 时只排除了 archived）

**建议**：补"已取消"筛选项，或在"全部"里也把 cancelled 隐藏。

## 3. 已完成 / 已取消的点位没从地图上下来

**现象**：`/map` 的点位只排除了 `archived`，已完成、已取消的委托照样挂在图上，点进去是结束状态的详情。

**复现**：把一条委托点成 `completed`（t1：接单 → 标记完成），或把另一条取消（t2），回到 `/map`，两个点都还在图上。

**期望**：地图对应"可接的委托"，结束状态不该出现。

**实际**：`campus-map.tsx` 里只过滤 `task.status !== "archived"`。

**位置**：`apps/web/src/components/campus-map.tsx`

**建议**：改成只画 `pending` / `in_progress`，或者按状态分图层、可切换。

## 4. 新发布的委托全叠在地图正中心

**现象**：发两条不同地点的委托，地图上只有一个图标，两条完全重合。

**复现**：`/tasks/new` 发两条，打开 `/map`。

**期望**：按地点落到不同位置（D3 做选点），至少没选点前要错开。

**实际**：`createTask` 里 `pin` 写死 `{ x: 50, y: 50 }`。

**位置**：`apps/web/src/lib/data/tasks.ts`（归 A，D3 选点后解决）

**建议**：接 Leaflet 前，先按 id 或坐标散列做小幅偏移，别叠死。

## 5. 顶部搜索框是个摆设

**现象**：header 里的搜索框能打字，敲回车什么都不发生，右边还标着 `/` 快捷键，按了也没用。

**复现**：在顶部搜索框输入"搬"，回车。

**期望**：跳到 `/tasks?q=搬` 或就地出结果。

**实际**：`app-shell.tsx` 里的 `<input>` 没有受控状态、不在 form 里、没有 keydown 处理。

**位置**：`apps/web/src/components/app-shell.tsx`

**建议**：包一层 form 提交到 `/tasks?q=`；做不完就先把搜索框和 `/` 提示撤掉，别让评委点了没反应。

## 6. 发布成功后再点一次会重复发布

**现象**：成功提示出来后，表单内容还在，按钮恢复可点，不改内容再点一次就多一条一模一样的委托。

**复现**：发一条 → 不修改 → 再点"发布委托"。

**期望**：成功后清空表单，或按钮变成"再发一条"。

**实际**：`created` 只控制提示，字段没重置，`pending` 结束后按钮恢复。

**位置**：`apps/web/src/components/task-form.tsx`

**建议**：成功后重置字段，或把按钮文案改掉、二次提交先确认。

## 7. 取消后进度条看起来像"待接单"

**现象**：详情页点"取消委托"，进度条仍把"已发布"标成完成，后三步灰着，和待接单状态一模一样。

**复现**：打开一条 pending 委托的详情 → 取消 → 刷新。

**期望**：取消是终态，应该整条置灰或单独标"已取消"。

**实际**：`task.status === "cancelled"` 时 `currentIndex = 0`，正好等于 pending 的渲染。

**位置**：`apps/web/src/app/tasks/[id]/page.tsx`

**建议**：cancelled 时隐藏进度条，或在 steps 里加一个"已取消"节点。

## 8. 界面上还留着"演示"字样

**现象**：详情页右上"演示详情页 · t1"、地图副标题"当前是演示地图，下一步接 Leaflet"、发布成功提示"演示环境存内存，重启后恢复 seed"、管理页"比赛演示用的内部入口"、信息库"当前是演示 seed"。

**复现**：按上面五处逐个打开。

**期望**：对外文案写成正式口径；"待接 Leaflet / 存内存"这类内部说明只留在代码注释或文档里。

**实际**：至少 5 处直接露在页面上，评委看站能看到。

**位置**：`app/tasks/[id]/page.tsx:44`、`app/map/page.tsx`、`components/task-form.tsx`、`app/admin/page.tsx`、`app/info/page.tsx`

**建议**：组件和详情页里的由 D 改，页面级介绍文案列给 E 统一改。

## 9. 列表接口把联系方式一起返回了

**现象**：`GET /api/tasks` 每条记录都带 `contact`，页面虽然没渲染，但接口是裸的；详情页也是谁点"查看联系方式"都能看。

**复现**：`curl http://localhost:3000/api/tasks`，看返回字段。

**期望**：列表不返回联系方式；详情里也应该等登录、接单后再给。

**实际**：`Task` 类型里 `contact` 是必填，列表直接返回整个对象。

**位置**：`apps/web/src/app/api/tasks/route.ts`、`src/lib/data/tasks.ts`（A 的领地）

**建议**：列表做字段裁剪，或等 D2 登录接上后按角色收口。这条先报给 A。

## 10. 移动端字号偏小

**现象**：全站大量 `text-[10px]`、`text-[11px]`（组件里各 53 处），375px 宽度下卡片里的地点、时间、辅助说明读着费劲。页面本身没有横向溢出，纯粹是字号偏小。

**复现**：DevTools 切 iPhone SE（375px），看 `/tasks` 卡片和 `/tasks/[id]` 详情。

**期望**：正文不小于 14px，辅助信息不小于 12px。

**实际**：组件和页面里 10/11px 遍地。

**位置**：`components/` 与各页面

**建议**：D4 打磨时统一抬到 12px 起，这条先记着，不在 D1 改。

## 11. 不存在的委托详情是"软 404"

**现象**：访问 `/tasks/not-exist-123`，页面渲染的是 404 内容，但 HTTP 状态码返回 200；真正不存在的路径（如 `/no-such-page`）才是 404。

**复现**：分别请求任意不存在的路径和一个不存在的委托 id，看状态码。dev（3000）和生产构建（next start）都是 200。

**期望**：不存在的详情页应该返回 404，便于监控、爬虫和后续 SEO 判断。

**实际**：200 + 404 页面内容。动态页面流式输出，响应头先发了 200，`notFound()` 抛出来的时候已经改不了状态码。

**位置**：`apps/web/src/app/tasks/[id]/page.tsx`（`notFound()` 调用）+ `loading.tsx`

**建议**：先记录，不急。要么去掉详情页的 `loading.tsx`/`force-dynamic` 让它在渲染前判定，要么接受软 404，别让监控把它算成正常页。
